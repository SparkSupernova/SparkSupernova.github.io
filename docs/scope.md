# Project Scope Statement

## Project Title

Spark Supernova Professional Portfolio

## Project Purpose

The purpose of this project is to create a concise, public-facing research
portfolio that accurately communicates the maturity and structure of my work
without exposing proprietary NovaLiveSystem implementation. The central
communication problem is not introducing a new interest in AI. It is translating
an established body of original theory, biomimetic architecture, trained models,
evaluation infrastructure, continuity products, and safety-centered applications
into a two-page format that remains legible to a general audience.

## Project Objectives

1. Present me accurately as an independent cognitive-systems researcher,
   founder, and architect—not as an entry-level AI developer.
2. Explain SparkPlugged as the R&amp;D organization connecting original theory,
   NovaLiveSystem, trained models, evaluation, EchoCopi, and SparkShield.
3. Build a functional two-page website using semantic HTML and one external CSS
   file.
4. Make the site readable and usable across desktop and mobile screen sizes.
5. Create documentation that shows how the project was scoped, planned,
   evaluated, and completed.
6. Publish the finished project through a professional public GitHub repository.

## Primary Stakeholders

| Stakeholder | Interest or Need |
| --- | --- |
| Course instructor | A complete, functional project that satisfies the technical and project-management requirements |
| General site visitor | A clear explanation of my professional identity and selected work |
| Potential collaborator | Direct access to verified public projects and professional profiles |
| Project owner (Ifejah Greene) | Accurate representation without proprietary disclosure or unnecessary scope |

## In Scope

- A semantic `index.html` homepage
- A linked `about.html` page
- One shared external `style.css` file
- Responsive layouts for desktop, tablet, and mobile screens
- Keyboard-accessible navigation and a skip link
- Public descriptions of SparkPlugged, NovaLiveSystem, and EchoCopi
- Public descriptions of RBH, Observation as Experience, Tri-Heartbeat
  synchronization, Memory Orbits, Nova Mind releases, and SparkShield
- Links to GitHub, LinkedIn, Hugging Face, and the SparkPlugged website
- A professional repository `README.md`
- Project-management documentation in a `docs/` folder
- Public deployment through GitHub Pages

## Out of Scope

- Private NovaLiveSystem source code, datasets, memory structures, or internal
  operational details
- Authentication, databases, forms, analytics, or server-side functionality
- E-commerce or product licensing workflows
- A blog, content-management system, or additional project pages
- Unsupported claims about performance or research outcomes
- Replacing the existing SparkPlugged company website

## Deliverables

1. Published two-page portfolio website
2. `index.html`
3. `about.html`
4. `style.css`
5. `README.md`
6. `docs/scope.md`
7. `docs/plan.md`
8. `docs/retrospective.md`
9. Clear Git commit history
10. Submission ZIP containing the complete project

## Constraints

- The final project deadline limits the amount of optional functionality that
  can be added.
- All content must remain appropriate for a public repository.
- The project must use plain HTML and CSS rather than a framework.
- The repository name and deployment URL are fixed by GitHub Pages.
- The site must remain understandable to visitors who do not have a technical
  background.

## Assumptions

- GitHub Pages will host static HTML and CSS from the `main` branch.
- The public professional links used in the site will remain available.
- External Google Fonts may fall back to local sans-serif and monospace fonts if
  a visitor blocks remote font loading.
- The project owner is the sole developer and project manager.

## Acceptance Criteria

The project is complete when:

- both pages load at the public GitHub Pages URL;
- navigation connects the homepage and About page without broken links;
- both pages use the same external stylesheet;
- the layout remains usable at narrow mobile widths;
- all three required project-management documents are present;
- the README links to both the live site and documentation;
- the repository is public and has a clear, staged commit history; and
- no proprietary information appears in the published files.

## Revision Note

The original project charter identified overscope and proprietary disclosure as
the two most important constraints. No formal peer-feedback artifact was
available in the course folder when this final scope was prepared, so I did not
invent feedback. A later content review identified a different form of scope
failure: excessive simplification. The first public draft protected the private
architecture but made the research appear newly formed and conceptually shallow.
The final revision preserves the two-page boundary while representing the actual
continuum from theory to architecture, models, evaluation, products, and
application.
